# vane-upload 浏览器功能回归手册

> 用途：每次功能增删后，用浏览器模式在 **30 分钟内**跑完一轮全功能回归。
> 本轮实测：2026-11-08，22 条用例 —— 20 条全通过、1 条部分通过（E3，受 F-02 影响）、1 条暴露缺陷（F-01）。
> 适用版本：`vane-upload@0.1.0`（本地 demo 页 `src/App.tsx`）。

---

## 一、30 分钟时间预算

| 阶段 | 内容 | 预算 |
| --- | --- | --- |
| P0 | 启动前后端 + 打开页面 + 冒烟（A1） | 4 min |
| P1 | 配置类：显示模式/自动上传/自动清理/延时/统计抽屉 | 4 min |
| P2 | 选择与校验：单文件/多文件/中文名/非法名/maxFiles | 4 min |
| P3 | 上传主链路：小/中/大文件、秒传 | 4 min |
| P4 | 中断类：暂停续传、取消续传、上传中删除 | 6 min |
| P5 | 异常类：后端停机失败、单条重试、批量重试 | 4 min |
| P6 | 恢复类：刷新恢复 + 零重选续传、批次详情、整批取消 | 4 min |
| — | 合计 | **≈ 26 min** |

> 时间紧时可跳过：A2（显示模式）、E3（批量重试）、G3（批次详情），仍有 85% 覆盖。

## 二、环境准备（P0，4 min）

### 2.1 启动后端（终端 1）

```bash
cd <项目根>
NODE_ENV=development PORT=3000 AUTH_MODE=demo RATE_LIMIT_ENABLED=false node server/src/index.js
```

- `AUTH_MODE=demo` 关闭鉴权，前端 demo 无需凭据；生产/联调请用 `secure` + `FILE_AUTH_TOKEN`。
- 就绪判据：`curl http://127.0.0.1:3000/api/health` 返回 `{"code":200,...}`。

### 2.2 启动前端（终端 2）

```bash
cd <项目根>
NO_PROXY=127.0.0.1,localhost npx vite --port 5173 --strictPort --host 127.0.0.1
```

- Vite 把 `/api` 代理到 `localhost:3000`。
- 若机器设置了 `HTTP_PROXY`，必须带 `NO_PROXY`，否则本地请求会走代理 502。

### 2.3 打开页面

- 地址：`http://127.0.0.1:5173/`
- 浏览器窗口宽度 **≥ 1000 px**：表格「操作」列固定在最右，宽度不足时需横向滚动才能看到行内按钮。

### 2.4 认识「测试注入口」（关键）

浏览器自动化（CDP/OS 层）**无法操作原生文件选择框**，因此 demo 页在开发环境挂载了一个注入面板
（`src/dev/fileInjectionPanel.tsx`，仅 `import.meta.env.DEV` 生效，生产与 `dist/lib` 库产物均不含）。
它用 `DataTransfer` 构造 `File` 并派发 `change` 事件，等效于用户真实选文件。

面板位置：**页面左下角**，标题「测试注入口（仅开发环境）」。

| 按钮 | 文件名 | 大小 | 分片数（chunkSize=1MB） | 用途 |
| --- | --- | --- | --- | --- |
| 小 512KB | 小-512KB.bin | 512 KB | 1 | 单分片最小通路 |
| 中 3MB | 中-3MB.bin | 3 MB | 3 | 常规多分片 |
| 大 12MB | 大-12MB.bin | 12 MB | 12 | 多分片 + 失败重试 |
| 中文名+空格 64KB | 中文名称 空格 文档.txt | 64 KB | 1 | 中文/空格文件名 |
| 含 test 名 4KB | test-被拦截示例.txt | 4 KB | 1 | 触发 customFileValidator |
| 11 个小文件 | 批量-1..11.bin | 64 KB ×11 | 1 | 触发 maxFiles=10 上限 |
| 3×40MB 队列 | 队列-1..3-40MB.bin | 40 MB ×3 | 40 ×3 | 制造稳定「上传中」窗口 |
| `[N]` + MB | 自定义-NMB.bin | N MB | N | 单个大文件（≤100MB） |

**「内容随机」勾选框**是秒传用例的开关：

- 勾选（默认）：每次注入内容不同 ⇒ 新 md5 ⇒ 真实上传。
- 取消勾选：内容按固定种子生成 ⇒ 同按钮重复注入 md5 相同 ⇒ 第二次命中**秒传成功**。

> 每个文件注入时 `lastModified` 都不同，避免被「同一文件重复选择」的内容指纹去重拦掉。

### 2.5 demo 页默认配置（`src/App.tsx`）

| 配置 | 值 | 影响用例 |
| --- | --- | --- |
| chunkSize | 1 MB | 分片数 = ceil(size/1MB) |
| fileConcurrency / chunkConcurrency | 2 / 2 | 多文件时出现「排队中」 |
| maxRetries | 3 | 失败重试次数 |
| maxFileSize | 100 MB | 超过即拒绝 |
| maxFiles | 10 | 超限整批拒绝 |
| autoUpload / autoCleanup / cleanupDelay | 开 / 开 / 5 s | 完成后记录会倒计时清理 |
| networkDisplayMode | tooltip | 徽标默认「简洁」 |
| customFileValidator | 名称含 `test` 或 >500MB 拒绝 | 校验用例 |

## 三、用例清单

> 状态语义（`src/components/ZustandFileUpload/types/upload.ts`）：
> 排队中 / 待上传 / 准备上传 / 上传中 / 已暂停 / 已完成 / 秒传成功 / 上传失败。
> **产物就绪的合法终态有两个：`已完成` 与 `秒传成功`**，断言时二者都算通过。

### A 组｜基础渲染与配置（8 min）

| ID | 功能点 | 操作步骤 | 预期结果 | 本轮 |
| --- | --- | --- | --- | --- |
| A1 | 初始渲染 | 打开 `/`，观察首屏 | 标题「上传组件演示」；工具栏 4 按钮（选择文件/上传文件/清除列表/批量重试，后三者在无文件时禁用）；网络徽标 `4G`；开关：自动上传=开、自动清理=开、延时=5；表头 7 列（编号/文件名/大小/分片数/状态/进度/操作）；空态「暂无数据」 | ✅ |
| A2 | 显示模式切换 | 点网络徽标右侧开关（简洁↔详细） | 切换后徽标在「4G」与「4G 1MB \| 2文件 \| 2分片」间变化，开关文案同步 | ✅ |
| A3 | 自动上传开关 | 关闭「自动上传」→ 注入「中 3MB」 | 记录进入列表但状态为 `排队中`、进度 0%，不自动开始；「上传文件」按钮可点 | ✅ |
| A4 | 手动上传 | 接 A3，点「上传文件」 | 状态 → 上传中 → 已完成 100% | ✅ |
| A5 | 自动清理 + 延时 | 开启「自动清理」，延时改为 `3`，注入「小 512KB」，等 5 s | 上传完成后约 3 s，记录自动从列表移除，回到「暂无数据」 | ✅ |
| A6 | 存储统计抽屉 | 点工具栏右侧柱状图图标 | 抽屉「存储统计」打开：总体统计（总文件数/总存储大小）+ 状态分布（按状态计数与占比、大小）；点右上 ✕ 关闭 | ✅ |

### B 组｜选择与校验（4 min）

| ID | 功能点 | 操作步骤 | 预期结果 | 本轮 |
| --- | --- | --- | --- | --- |
| B1 | 单文件入队 | 点「小 512KB」 | 新增 1 行，1 分片，自动上传至 `已完成` | ✅ |
| B2 | 多文件入队 | 点「3×40MB 队列」 | 新增 3 行；多数情况下并发=2 ⇒ 2 行 `上传中` + 1 行 `排队中`（网络自适应重估后可能出现 3 行同时 `上传中`，两者都算通过） | ✅ |
| B3 | 中文名 + 空格 | 点「中文名+空格 64KB」 | 正常入队并上传完成，文件名完整显示 | ✅ |
| B4 | 自定义校验拦截 | 点「含 test 名 4KB」 | 顶部红色提示 **「文件名包含 test 时不允许上传」**，列表不新增记录 | ✅ |
| B5 | maxFiles 上限 | 列表已有 2 条时点「11 个小文件」 | 红色提示 **「最多只能选择 10 个文件（当前已有 2 个）」**，整批拒绝 | ✅ |
| B6 | 清除列表 | 点「清除列表」 | 列表清空回到空态；上传进行中时该按钮禁用 | ✅ |

### C 组｜上传主链路与秒传（4 min）

| ID | 功能点 | 操作步骤 | 预期结果 | 本轮 |
| --- | --- | --- | --- | --- |
| C1 | 多分片上传 | 点「大 12MB」 | 分片数=12，进度到 100%，状态 `已完成`；顶部「上传成功」+「批量上传完成: 成功 1 个, 失败 0 个」 | ✅ |
| C2 | 大文件上传 | 自定义 `95` MB → 点「MB」 | 95 分片，进度平滑上升（显示速率/剩余），终态 `已完成` | ✅ |
| C3 | 秒传 | 取消勾选「内容随机」→ 注入「中 3MB」→ 等完成 → 清空列表 → 再注入「中 3MB」 | 第二次状态直接为 **`秒传成功`**，耗时明显更短（毫秒级） | ✅ |
| C4 | 服务端产物一致性 | 上传后用 `md5` 值在 `server/uploads/` 找到产物（文件名含 md5、size、chunkSize）并比对大小 | 产物大小 = 源文件大小 | ✅ |

### D 组｜中断类（6 min，时序敏感，按步骤顺序执行）

| ID | 功能点 | 操作步骤 | 预期结果 | 本轮 |
| --- | --- | --- | --- | --- |
| D1 | 暂停 → 继续 | 点「3×40MB 队列」，**立刻**点第 1 行「暂停」 | 该行 `已暂停`，进度保留；其余行继续 | ✅ |
| D2 | 从断点续传 | 接 D1，点该行「继续」 | 从原进度继续，终态 `已完成` 或 `秒传成功` | ✅ |
| D3 | 取消 → 继续 | 点「3×40MB 队列」，立刻点第 1 行「取消」 | 该行 `已暂停`（进度保留），**记录不删除**；点「继续」→ 续传至完成 | ✅ |
| D4 | 上传中删除 | 点「3×40MB 队列」，立刻点第 1 行「删除」 | 该行立刻消失，其余行不受影响（上传中被真实中止） | ✅ |

> **D 组操作要点**：本机 40 MB 约 3 s 完成，工具调用有 0.5~1 s 延迟，所以必须
> 「注入 → 紧接着点行内按钮」两步连做，中间不要插入截图或 DOM 读取。
> 暂停在进度 100%（合并阶段）点也有效，此时继续后终态为 `秒传成功`。
> 若窗口内没点中，行会正常完成，重新执行该用例即可。

### E 组｜异常与重试（4 min）

| ID | 功能点 | 操作步骤 | 预期结果 | 本轮 |
| --- | --- | --- | --- | --- |

## 四、本轮缺陷与观察

### F-01（已确认缺陷，P2）｜整批「取消上传」后列表状态不刷新

- **复现**：注入「3×40MB 队列」→ 上传中点「详情」→「取消上传」。
- **现象**：上传实际已停止（`上传文件`/`清除列表` 恢复可用，`du -s server/tmp` 不再增长），
  但部分行仍显示 `上传中` + 进度 100% + **冻结的速率**（如 7.0 MB/s），既不能「继续」也不报错，只能删除或刷新。
- **自愈**：刷新页面后，本该完成的变为 `已完成`，未开始的行变为 `上传失败`（分片缓存已被整批取消清空）。
- **影响**：用户会以为任务卡死；失败行缺少「需重新选择文件」的引导文案。
- **建议**：`cancelUpload` 中止后，对残留 `UPLOADING/排队中` 记录统一落定为 `已暂停` 并清空 speed/eta。

### F-02（观察，非缺陷）｜整批取消后失败行重试静默无效

- 整批取消会清理该文件的分片缓存，此后该行「重试」不会成功（无 fileRef，需要重新选择文件），
  但界面仍只显示 `上传失败`，没有「需重新选择文件」提示。属既有降级设计，建议补文案。

## 五、回归判定标准

一轮回归**通过**需同时满足：

1. A~F 全部用例的「预期结果」逐项命中；D 组允许因抢不到时序而重跑一次。
2. 浏览器控制台无 `pageerror`（未捕获异常）。
3. 后端 `/api/health` 全程 `code=200`，`chunkQueue.degraded=false`。
4. 缺陷区（F-01/F-02）状态与上轮一致，没有新增缺陷。

## 六、常见问题

| 现象 | 原因与处理 |
| --- | --- |
| 页面能开但上传全失败 | 后端没起或 `AUTH_MODE` 不是 demo；先 `curl /api/health` |
| 请求 502 / 页面白屏 | 环境里存在 `HTTP_PROXY`，启动时补 `NO_PROXY=127.0.0.1,localhost` |
| 看不到「操作」列 | 浏览器窗口宽度 < 1000 px，拉宽窗口（或横向滚动表格） |
| 点「选择文件」没反应 | 原生文件框无法被自动化驱动，请改用左下角「测试注入口」 |
| 记录上传完就消失 | 「自动清理」开着且延时到了，属预期；回归时先关闭它 |
| 注入后全部秒传 | 「内容随机」没勾选，第二次同内容必然秒传 |
| 想验证服务端落盘 | `ls server/uploads/`，产物名形如 `u<hash>_<md5>_<size>_<chunkSize>_<md5>.bin` |

## 七、附：注入口的实现约束（改动前必读）

- 文件：`src/dev/fileInjectionPanel.tsx`；挂载点：`src/main.tsx` 中 `if (import.meta.env.DEV)` 动态 `import`。
- **不进库产物**：`vite.lib.config.ts` 入口为 `src/index.ts`，不含 `main.tsx`/`dev/*`。
- **不进生产包**：`import.meta.env.DEV` 为 `false` 时整块（含动态 import）被摇树移除。
- 注入原理：`document.querySelector('input[type="file"]')` → `DataTransfer` 写 `files` → 派发 `change`。
  组件只依赖原生 `onChange`，因此该方式等价真实选择；若未来改成拖拽区上传，需同步补一个 DnD 注入按钮。
- 新增预设时保持：`name` 可读、`size` 落在 1MB 分片边界附近更有区分度、`seed` 固定以便秒传复现。
