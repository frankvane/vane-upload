## 五、场景明细（通过项）

### S01 单文件上传（3 KB）

**步骤**：无限速 → 选择 `r2-single-3kb.txt` → 自动上传 → 观察终态与磁盘结果。

**预期**：`instant → status → upload → merge` 全部 200，列表「已完成 100%」。

**实际**：
- `POST /api/file/instant` 200、`GET /api/file/status` 200、`POST /api/file/upload` 200、`POST /api/file/merge` 200。
- 分片文件键 `2b90db67cb2dd049cb20c008a9887957_3072_1048576`，界面 1 片、已完成 100%。
- `server/uploads` 出现对应 3072 字节文件。

**结论**：✅ 通过。

### S02 多文件批量上传

**步骤**：一次选择 `r2-single-3kb.txt` + `r2-batch-2mb.csv` + `r2-big-10mb.bin`（或多文件批次含 12 MB），观察批量栏与每行终态。

**预期**：全部完成，分片数与实际请求数一致，批量栏汇总正确。

**实际**：
- 3 KB → 1 片、2 MB → 2 片、12 MB → 10 片（chunkSize 由网络策略决定），全部「已完成 100%」。
- 批量栏显示与行状态一致；服务端 `server/uploads` 出现对应 txt/csv/bin 文件。
- 每文件均完整走 `instant → status → upload×N → merge`。

**结论**：✅ 通过。

### S03 分片切片与并发控制

**步骤**：Slow 4G 下上传 12 MB 文件，观察同时进行的 `POST /api/file/upload` 数量与进度推进。

**预期**：`fileConcurrency=2`、`chunkConcurrency=2` 生效，同时最多 2 个文件任务、每个任务最多 2 个分片在途；进度与已完成字节一致。

**实际**：
- 网络面板同时存在 **2 个 pending** 的 `POST /api/file/upload`（并发受控，未出现 10+ 并发刷屏）。
- 行内百分比与请求完成数量同步推进，无「100% 但仍在传」或「已完成但请求未结」。
- 暂停时在途请求被中止，服务端日志出现 `POST /api/file/upload - - ms`（无完成耗时，连接中断）。

**结论**：✅ 通过。

---

### S06 暂停 / 继续

**步骤**：Slow 3G 上传 8 MB 文件 → 2% 时点「暂停」→ 观察 → 点「继续」→ 网络恢复无限速 → 观察终态。

**预期**：暂停后不再发分片，状态「已暂停」；继续从断点而非 0 开始；最终完成。

**实际**：
- 暂停后行显示「已暂停 2%」+「继续 / 删除」按钮；暂停期间无新增 `upload` 请求。
- 点「继续」从 **2%** 续跑（非归零），随后切换无限速完成 100%，共 32 片（8 MB / 256 KB），`merge` 200。
- 恢复网络后 chunkSize 保持选择时确定的 256 KB（会话内稳定）。

**结论**：✅ 通过。

### E2E-R1 刷新后列表持续为空（P0，新回归）

**现象**：刷新后 IndexedDB 有记录，但列表 8 s 内始终「暂无数据」，顶部操作按钮全部禁用；再次选择文件后旧记录才突然出现。

**证据**：
- `indexedDB.databases()` → `react-upload-indexeddb`，`upload_files.count = 1`。
- DOM t0/t+4 s/t+8 s 均包含「暂无数据」，无行。
- 再次选文件后行立即出现（同一份 IDB 数据）。

**根因（代码定位）**：`StrictMode` 双挂载 + `hasRecoveredOnceRef` 提前返回 + `disposed` 丢弃首个异步结果（[index.tsx](file:///e:/vane-upload/src/components/ZustandFileUpload/index.tsx#L100-L145)）。

**影响**：刷新即「丢数据」的观感，且用户无法通过刷新恢复任何记录；同时让 E2E-01/02 的验证入口被隐藏。

**建议**：恢复逻辑不应依赖只执行一次的 ref 或卸载丢弃；StrictMode 下应允许第二次 effect 应用结果（或用 `AbortController` 之外的幂等快照写入 store）。

### E2E-R2 非法扩展名到 `/merge` 才 415，行内无失败原因（P1）

**现象**：`r2-alien.exe`（512 KB）在无白名单的前端被放行并完整上传所有分片，最终 `POST /api/file/merge` 返回 415；行显示「上传失败 100%」，进度条红色 100%，重试按钮 `title` 为空，行内无原因，仅短暂 toast。

**请求/响应证据**：
```json
POST /api/file/merge → 415
{"code":415,"message":"file extension .exe is not allowed","data":{"extension":"exe","reason":"dangerous-extension"}}
```

**影响**：浪费全部流量与分片落盘后才失败；用户看不到失败原因，容易反复重试。

**建议**：前端接入 `fileType.ts` 白名单提前拦截；或至少把服务端 `message` 渲染到行内 / 重试按钮 tooltip；上传前用轻量校验接口（如 `instant` 阶段）返回扩展名策略。

### E2E-R3 历史失败记录被新批次自动重试（P1）

**现象**：任意新选择文件触发 `autoUpload` 时，列表里的历史 `ERROR` 记录（如 `r2-alien.exe`、刷新中断记录）会被一并重新入队；批量栏出现「上传完成，失败 N 个」，`.exe` 每次批次都再次 415。

**证据**：`uploadAll` 用 `isUploadableStatus` 过滤，`ERROR` 被视作可上传；新增文件触发批次时重复观察到 `POST /api/file/upload/merge` 命中 `r2-alien.exe`。代码位置：[useBatchUploaderController.ts](file:///e:/vane-upload/src/components/ZustandFileUpload/hooks/useBatchUploaderController.ts) 的批量入队逻辑。

**影响**：无意义流量、失败计数污染、用户以为新批次失败。

**建议**：自动上传批次只处理本次新选择的文件；`awaitingReselect` 或「历史失败」记录需用户显式触发重试。

### E2E-R4 取消上传入口缺失（P2）

**现象**：界面只有「暂停」「删除」，没有「取消」；上传中删除被禁用，因此无法「取消并清除」。

**影响**：用户只能暂停后删除，或等待完成；取消语义（清空队列 + 中止任务 + 清理服务端分片）不可达。

**建议**：补充「取消」动作并在 Worker 侧 cancel + 清理分片，或允许删除进行中任务且真正 abort。

- 仅 Chromium 实测；`indexedDB`、`navigator.storage.estimate()` 在隐私模式/旧版浏览器下可能不可用，此时按设计降级为方案 C（提示重新选择）。
- 单文件缓存不再有固定 512 MB 门槛：默认按 `quota - usage` 预留 20% 余量后是否够容纳「尚未确认上传的分片字节」决定；`chunkCacheMaxFileSize` 仅作可选上限（默认 `Infinity`）。
- 配额压力下浏览器仍可能自行淘汰缓存（此时同样走降级提示）；已尝试 `navigator.storage.persist()` 降低该概率，但无法完全避免。

### 10.1 空间准入策略复验（大文件 / 空间不足）

> 背景：默认固定上限 512 MB 会让大文件续传失去意义，已改为按 `quota - usage` 的真实可用空间（预留 20%）判断，判定对象为「尚未确认上传的分片字节」。浏览器实测（Chromium，独立数据目录）：

| 场景 | 关键证据 | 结论 |
|---|---|---|
| 256 MB 大文件刷新续传 | 哈希 + 缓存预热后行出现耗时 7.3 s；刷新前缓存 254/256 片、meta=`ready`，`estimate` 显示 usage≈255 MB / quota≈10.5 GB；服务端已收 chunk `[0,1]`；刷新后行显示「上传中」并自动续传 256 个请求，25.8 s 完成，`/instant` 校验 `true`，磁盘产物 md5 命中；完成后缓存 `target=null` | ✅ 通过 |
| 可用空间不足降级 | 注入 `quota=100 MB / usage=96 MB`（可缓存约 3.2 MB < 6 MB）：选择文件后立即出现「浏览器可用空间不足」提示，分片缓存无任何记录；刷新后行显示「上传失败」，状态 Tag `title` = 「检测到页面刷新导致上传中断，本地续传缓存缺失，请重新选择文件」，自动续传请求 0 个 | ✅ 通过 |
